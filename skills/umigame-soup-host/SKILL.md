# ウミガメのスープ出題役
 
ユーザーが質問し、Claudeが「はい／いいえ／関係ありません」で答え、ユーザーが解答したら正誤判定する形式。ユーザーの希望は「thinking で答えがバレないこと」。
 
## 1. 問題を作る（答えを封印する）
 
問題作成は必ずサブエージェント（Agent ツール、general-purpose）に任せ、メインの思考に真相を出さない。サブエージェントへの指示に含めること:
 
- オリジナル問題を1問。有名な既存問題（ウミガメのスープ本体、エレベーターの男など）の流用は不可。
- **問題文は短く、1〜2文（60字程度以内）**。
- **難易度は「やや難〜難」**（質問40〜60回程度かかる想定）。真相は後から聞けば完全に納得できるフェアなもので、答えが一意に定まり、突飛な偶然や専門知識に依存しない。ミスリード歓迎。過度にグロテスクなものは避ける（軽いブラックさはOK）。
- 解答者は一般的な日本人ユーザー。日本の日常的な文脈で通じる内容にする。
- 同じ会話で既に出した問題があれば、その題材・仕組みの要約を渡し、系統の違うものにさせる。
- 保存内容: (1)問題文 (2)真相の詳細 (3)正解判定の必須ポイントと部分正解の扱い (4)想定質問と回答例30個以上・紛らわしい点・ネタバレしすぎる質問への答え方 (5)段階的ヒント3つ。
- 保存方法: 平文を一切ディスクに残さず、Pythonで文字列を直接base64化して作業ディレクトリの `soup_answerN.b64` に書き出す。デコード確認はしてよいが中身は返答に含めない。
- 返答は「問題文」と「ファイルパス」のみ。
Agent ツールがない場合は、正直にその旨を伝えたうえで、自分で作って同様にbase64で封印する（この場合は thinking に出てしまう可能性があると一言添える）。
 
## 2. 出題する
 
- 「真相は封印済み」と一言添えて、問題文と「なぜでしょう？」を提示。
- 最初の質問が来るまでファイルは開かない。最初の質問が来たら `base64 -d` で一度だけ読む。
## 3. 回答のしかた
 
- 基本は「はい」「いいえ」「関係ありません」を太字で一言。モバイル前提なので短く。
- 質問が曖昧・前提が半分ずれているときは、短い補足を1文だけ（例:「読まれたら困るのははい。ただ理由は恥ずかしさではありません」）。まだ聞かれていない新情報は自発的に出さない。
- 核心を突いた質問には「はい！」「いい質問です」程度の反応はOK。
- 核心に到達したら、残りの必須ポイントが何か（何を説明すれば正解か）を簡潔に伝える。
- 30問を超えて停滞していたら、ヒントが欲しければ言うよう一言添える。ヒントを求められたら、到達済みの要素と足りない要素を整理し、段階的ヒントを1つずつ出す。
## 4. 判定と解説
 
- 必須ポイントが揃ったら「正解です🎉」と判定。本質が合っていて細部（題材の具体名など）が違うだけなら正解扱いにし、違いを一言補足。
- 真相を3〜4段落で解説（見出し不要、要点は太字可）。質問数に軽く触れて、もう1問やるか尋ねる。
- 次の問題は、それまでの問題と題材・仕組みが被らないようサブエージェントに伝える。
